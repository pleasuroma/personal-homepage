# Interview Me

작업에 들어가기 전에 사용자의 의도를 정확히 파악하기 위한 짧은 인터뷰를 진행한다. 목표는 "넘겨짚기"를 없애는 것이다.

## 언제 실행하나
- 요청에 **Why(목적)** 또는 **완료 기준(Done)** 이 빠져 있을 때
- 결과물의 형태·대상·범위가 여러 갈래로 해석될 수 있을 때
- 사용자가 명시적으로 요청할 때

요청이 이미 충분히 구체적이면 인터뷰를 생략하고 "이해한 내용"만 한 줄로 확인한 뒤 진행한다.

## 진행 방법
1. 요청을 읽고 **이미 알 수 있는 것**과 **모르는 것**을 구분한다. 코드·파일·대화에서 확인 가능한 것은 묻지 않는다.
2. 아래 항목 중 빠진 것만 질문한다. 한 번에 1~3개, 중요한 것부터.
   - **Why**: 이걸 왜 하나? 해결하려는 문제는?
   - **완료 기준**: 무엇이 되면 "끝났다"고 볼 수 있나?
   - **대상/사용자**: 누가 쓰거나 보나?
   - **범위**: 꼭 포함할 것 / 하지 말아야 할 것
   - **제약**: 기한, 형식, 도구, 스타일, 분량
   - **참고 자료**: 예시, 기존 결과물, 선호하는 방향
3. 질문할 때는 가능하면 **선택지 + 추천안**을 함께 제시해 답하기 쉽게 한다. (AskUserQuestion 같은 도구가 있으면 사용)
4. 답변에 따라 꼬리 질문은 필요한 만큼만 한다. 총 질문은 보통 3~7개를 넘기지 않는다.

## 마무리: 작업 브리프
인터뷰가 끝나면 아래 형식으로 요약하고 사용자 확인을 받은 뒤 작업을 시작한다.

```
## 작업 브리프
- 목적(Why):
- 완료 기준:
- 대상:
- 범위(포함 / 제외):
- 제약:
- 진행 계획: 1) … 2) … 3) …
```

사용자가 "좋아", "진행해" 등으로 확인하면 브리프를 기준으로 작업하고, 작업 중 브리프와 어긋나는 판단이 필요하면 다시 짧게 확인한다.
